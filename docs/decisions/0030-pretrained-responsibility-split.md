# 0030 — Prioritize a compact pretrained detector; close shared rule gaps first

Date: 18 September 2026. Status: responsibility split measured; no release checkpoint or changed product scope approved.

The owner approved continuing the sustainable pretrained direction after deferring custom MiniLM training. Run a bounded comparison using the existing pinned models and 362 observed cases. All five configurations reproduce prior unrestricted outputs exactly. Narrowing model responsibilities to names/addresses/organizations reduces some unwanted masking but loses structured values supplied by the broad PII models. Preserve those losses and the unchanged failed screening results.

Keep Underthesea INT8 as the compact contextual engineering candidate (205.5 MB existing assets) and BigMed as the broad single-model comparison control (872.6 MB). This prioritization does not replace the installed pair or approve a model for release. Underthesea's name misses, excess masking, native offset integration and sparse upstream provenance documentation still need resolution. BigMed's lower name coverage and size prevent treating it as an automatic fallback. Neither pretrained availability nor a metadata license declaration establishes sustained upstream maintenance.

First remove dependence on contextual models for clearly specified structured syntax: labelled cards/security codes/PIN, IPv4, the tab-separated account gap and bounded written birth dates. Add strong ordinary-value contrasts, retain complete opaque spans and existing category behavior. Do not enable new no-pack choices or silently broaden/narrow the UI promise. Next inspect compact contextual errors, especially Unicode, whole-value boundaries and ordinary text, under unchanged weights. A new evaluated source version is required for any core change; old protocols remain frozen.

The main diagnostic's raw `local` helper route is not the UI engine. A separately frozen actual-engine check documents 72/73 and 53/53 selected-scope values, distinct from all-scope totals. Preserve that correction rather than presenting helper capabilities as shipped no-pack features.

Keep custom training deferred, avoid another overlapping model and do not start an open-ended model search. If remaining contextual failures prevent a defensible scope, bring that limitation to the owner rather than manufacture a passing model decision. Manual reviews and versioned upgrades remain necessary; user input/corrections are never collected. See the [comparison and maintenance recommendation](../evaluations/pretrained-scope.md).
