# 0172 — One home for the whole job: hide, then get the full version back

Date: 29 October 2026. Status: on the branch `redesign-task-first`, so it can be dropped in one step. The owner asked for the sidebar "and everything" to be easy for people who are not technical, without being bound to the accepted layout.

## Why

The sidebar listed formats: Văn bản, Bảng tính, Tài liệu, Thư mục, with file extensions under each ("XLSX, XLS, ODS, CSV") and a faded "Hình ảnh · Sắp có". People think in what they want done ("hide the names in this contract"), not in which kind of file they hold; whether a PDF is a Tài liệu is a question the app can answer. The home box already took every format and opened the right page, so the format entries were a second, harder way to start. The step people find hardest to grasp, putting the real names back into the AI's answer, was step 3 inside whichever page the text had been masked on, reachable only through that ## What changes

- **A new-task button, then the list.** The format entries and the coming-soon image entry go. The sidebar opens with "+ Ẩn thông tin mới", which goes home on its first tab, from home too, and the list below it is always there, with an empty line when nothing is open: the layout people know from the chat apps they paste into. The button is an action, never marked as the current page: shown outlined on home it read as selected, and the owner asked whether it was clickable; it now has a raised look and lifts under the pointer. A first version gave the two tasks an entry each ("Ẩn thông tin riêng", "Nhận lại bản đầy đủ"); a second kept a lone "Trang chủ", which the owner found odd. The text, spreadsheet, document and folder pages are unchanged inside; files still open on the right one.
- **The sidebar folds.** In a wide window a button beside the logo folds the sidebar away; the content takes the width and the logo flies to the centre of the top bar, turning once on the way (clockwise out, counter-clockwise back, a slight lift at mid-flight), and back when the button now at the top left opens it again. The sidebar's grid column shrinks while the sidebar slides left by the same amount on the same 560 ms ease-in-out curve, both sized by one `--sidebar-width`, so its edge stays on the content's at every frame (measured: 0 px apart throughout, frames under 10 ms in the preview). The logo's landing place is measured from one layout pass of the end state with transitions off; a copy flies there above the page while both real logos wait hidden, and lands on a timer too if the window stops painting mid-fold. A first version used a view transition, which crossfaded snapshots of the page and read as less smooth. The mark is a ninja's mask, and the owner asked for a ninja's move that stays light: the logo crouches leaning back against the way it will go, its name vanishes in a puff of smoke, the mask springs 18 px up an arc into one somersault (a flip seen side-on; more turns read as a blur, none as a hop) with two fading afterimages 45 and 90 ms behind, and lands at 86 % of the flight in a second puff, tipped 12° past upright with a squash before it settles, the name back (`src/composables/brandFlight.ts`). Only transform and opacity move, on three copies of the logo and six dots per puff; in the preview a fold kept frames at 9 ms. Opening stalled once for about 0.7 s in the preview with no script running, before this change as after it; the Mac app showed no such stall to the owner. For consistency the website's top logo leaves the same way (`setupNinjaLogo` in `landing/product.js`), in place of decision 0141's scrubbed lift-and-fade: past the first 90 px of scroll it crouches leaning back, springs up into a turn and is gone behind a ring of pale smoke drawn around the chip; back at the top it drops in through the smoke, turning, lands tipped past upright with a squash and settles. It is played once per crossing with GSAP's ScrollTrigger callbacks, not scrubbed, and moves only transform and opacity. With reduced motion, or without the script, 0141's behaviour stands. Clicks during a fold are ignored; reduced motion simply switches. The state lives in memory: each launch starts with the sidebar open, and nothing is stored. Narrow windows keep their drawer. Because the sidebar is often folded, the website link and the version moved from its foot to a footer on every page, pinned to the window's bottom with the page scrolling under it: a hairline, "OfflineMask.com" on the left, the version as a small pill on the right. A step's action row, pinned to the bottom too, now sits just above it. Cài đặt still shows the version, and the report still carries it.
- **What is open.** Below "Trang chủ", with a passcode, "Lịch sử" as before. Without one the list is "Gần đây" (first "Đang mở", which the owner found confusing, then "Đã ẩn", which did not fit a folder chosen but not yet hidden; its empty line was "Việc bạn đang làm sẽ hiện ở đây.", now "Văn bản và tệp bạn ẩn sẽ nằm ở đây."): the results of this launch, which live in RAM and replace each other per format as before (decision 0072), plus a folder being masked with its status ("Đang ẩn · 40%"). Before, without a passcode the format entries were the way back to a result; with them gone the list is. Nothing new is stored. The owner asked how this list differs from "Lịch sử" and wanted it explained where it is, so decision 0071's "nothing talks about saving" gives way in one place: an "i" beside the heading opens a note, on hover or focus, or held by a click until focus leaves, "Chỉ giữ đến khi bạn đóng ứng dụng. Mỗi loại chỉ giữ bản mới nhất. Đặt mật mã để lưu tất cả trên máy này, mở lại khi cần.", with "Đặt mật mã", which opens Cài đặt with the passcode form open and in view. With a passcode there is no "i". The owner liked the note and asked for the same in place of the browser's `title` tooltips across the app, and for unneeded ones to go. `v-tip` (`src/directives/tip.ts`) shows the same card, without a button, after 350 ms under the pointer or at once on keyboard focus, from one element in the page placed under its target (above when there is no room, inside the window), with `aria-describedby` while shown. It names the two icon-only sidebar buttons, says what each detection option covers, and gives the hide button's shortcut (⌘ Enter, or Ctrl Enter outside Apple systems). Three titles went: step 1's "Sửa văn bản rồi ẩn lại" and "Sửa văn bản"'s "Bản này vẫn được giữ trong lịch sử", both saying what the button already says, and a quick-action place's app name over its address.
- **Home in the website's voice.** The heading is the website's tagline, "AI không nên biết bạn đang nói về ai.", with the same cobalt italic serif and hand-drawn swash, over its subtitle. Two of the website's chips, a struck-out value beside its code (Phong Phan → [TEN_1_4e8c]), replace the three-panel illustration: one look explains what a "mã" is.
- **Two tabs, the website's step names.** Under the hero a large switch: "Ẩn thông tin riêng" and "Nhận lại bản đầy đủ". The first is a large drop target titled "Chọn hoặc kéo tệp, thư mục vào đây" in one line (a file or a folder; a click chooses a file) that names everything it opens as badges people recognise: Word, PDF, Excel, CSV, OpenDocument, Văn bản, Cả thư mục, each with its extensions. Under it a box that looks like a text field, "Hoặc gõ, dán văn bản vào đây…", opens the text page with the cursor in it; a link reading "Gõ hoặc dán chữ" was too easy to miss. Then "Chọn cả thư mục", "Xem thử với ví dụ" and "Thông tin của bạn không rời khỏi máy này." A list of the three steps sat under it for a day; the owner found it dull, and the two tabs say the same.
- **Nhận lại bản đầy đủ.** A pasted reply is restored with every alias this launch knows: each private session's table, kept in RAM by quick actions even after it was replaced (the same tables Ẩn nhanh restores with), and a masked folder's. Aliases carry their run's scope, so nobody has to say which text, file or folder the reply is about, and an alias of nothing known is kept and named, never guessed (PRD FR-09). A returned file (Word, OpenDocument, Excel, CSV, .md, .txt) is restored the same way with the existing returned-file code, which now takes any alias table (`openReply`). Before anything is masked the tab shows what it will do, an AI reply in which the codes turn back into a name and a phone number (the hero's swap read backwards), says there is nothing to get back yet and leads to the first tab; a first version was a line of text over a button in a footer. Pasting anywhere on home (outside a field) a text with known aliases opens this tab with it, so the user need not choose; other text still opens the text page. Step 3 inside each page stays for people already there.
- **Words.** "Báo lỗi" becomes "Báo lỗi hoặc góp ý". Settings keep their headings: they are already plain, and the pack's name is pack data (`desktop/packs/<id>.json`), not code.
