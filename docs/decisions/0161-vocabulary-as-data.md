# 0161 — The rules' vocabulary becomes data in one place; words are compared with their tone marks

Date: 27 October 2026. Status: implemented and measured, before the 2.3.0 push. Owner, after 0160: "the algorithm should be maintainable, dynamic and easy to extend, don't just add ten thousands of 'if', it's never enough", then "cannot push with this kind of dirty and messy code, do the consolidation before doing it. If we want to add more vocabularies, so at least we need to research and download it somewhere, don't just add one by one, and at least we will have data files in a centralized place, not just put it randomly all files."

## What was wrong

Decisions 0154 to 0160 closed measured families one by one. Each fix was right on its own; together they left word lists in seven rule files as regex literals, several of them folded by hand (an unaccented copy next to the accented one), and the legal-prefix walker carried guards that existed only because it compared words with their tone marks stripped: "tại" against "tải", "phòng" against "phong", "đã" against "đa khoa". A new kind of document would have meant more of the same.

## Decision

1. **One place for words.** `desktop/src/core/detection/vocabulary/` holds seven JSON files, each with a `$comment` naming its source and license, and a README that says which mechanism reads which file and the rules for adding to them. `vocabulary.ts` compiles them once into the sets and regex sources the rules use; no rule file holds a word list any more.

   | File | Source |
   | --- | --- |
   | `places.json` | generated by `scripts/build-places.mjs` from two MIT datasets: the 34 provinces and cities since Resolution 202/2025/QH15 (thanglequoc/vietnamese-provinces-database) and the 63 names before (tranngocminhhieu/vietnamadminunits); 31 former names remain after the merger; countries curated |
   | `public-bodies.json` | provincial departments from Decree 45/2025/NĐ-CP articles 8–9 (12 uniform, 4 only in some localities), former names from Decree 24/2014/NĐ-CP; state bodies and agencies curated |
   | `people.json` | 200 family names from Wikipedia, "Vietnamese name" (CC BY-SA 4.0); name syllables, forms of address, ranks and roles curated |
   | `organizations.json` | legal forms (Law on Enterprises 2020), organization kinds, units inside an organization with the words after which they are not units, trade syllables, compounds, the words that end a name |
   | `document-wording.json` | boilerplate by document kind, words before a number, column headings and labels that hold wording, amount words, currencies, contract parties |
   | `field-labels.json` | the labels before a name, address, birth date, account, identifier or code |
   | `units.json` | measures, packs, units of goods and services, the words of an address |

   No licensed corpus of Vietnamese given names exists (the search covered GitHub, Hugging Face and research datasets; the one open persona dataset carries no name field), so the name syllables stay curated and the file says so.

2. **Words are compared with their tone marks.** Entries are written as documents print them; the loader folds a copy only for the two readers that work on folded text (labelled fields, the walker's legal prefix). The walker now reads the original word: "tải" is a trade syllable and "tại" is not, "Phòng" is a unit and "Phong" is a name, "đã" ends a name and "đa khoa" is a compound. The guard map, the tone-mark check and the exception list that did this by hand are gone. A word written without any tone marks (a bank statement's "TAN PHONG") is answered by its folded form, so unaccented text keeps working.

3. **Fewer mechanisms, each reading data.** What remains in `model-policy.ts`: a span inside a phrase; a cell under a wording heading; a value after a wording label; a public body with its jurisdiction; the place of issue; a department, in one function; a name in capitals; a sex; a country or province; an organization's kind alone; a trailing "Số" or house number on an organization. `context-fields.ts` keeps the legal-prefix walker with three stop conditions, all from the vocabulary. `banking.ts` builds its five identifier rules with one helper. The department rule's five branches became one window test. The duplicate syllable and folding helpers in `model-policy.ts` are the ones in `person-cues.ts`.

4. **Adding words has a procedure** (the README): closed public sets are downloaded from a named source and regenerated by a script; curated lists say so; an open class (positions, products, subjects) is the models' job, with the synthetic set as their training and measurement data, not a list's.

| Owner's invoices | 10 | 0 → 0 | 0 → 0 | 0 → 0 | 0 → 0 |
| Owner's decision | 1 | 0 → 0 | 0 → 0 | 0 → 0 | 0 → 0 |

The report of every folder says "No change since" the run of 0160: the behaviour is the same to the value.

`pnpm test` 421 (a `vocabulary` test checks every file names its source and holds no duplicates), `pnpm test:models` 23/23, lint and typecheck pass. `model-policy.ts` went from 805 lines to 600. The seven rule files together hold 1 713 lines (1 575 before): each list became a short builder that reads the vocabulary, and the 1 728 lines of words now sit in the seven data files, where a reader can see them with their source.

## What this does not do

It does not make the lists complete. The open classes still produce false positives on wording nobody listed; the next step is to train or fine-tune the pack's models on the synthetic set so the vetoes shrink, with the owner's real files as the check that invented documents resemble real ones.
