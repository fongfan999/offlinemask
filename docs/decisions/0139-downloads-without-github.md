# 0139 — Downloads without GitHub, and the newest version at a glance

Date: 25 October 2026. Status: implemented. Owner: the app is live on the Microsoft Store (`9PN76BSDNRQW`); "study the Dia browser and improve the download section… For Mac and Linux, just show options to download, never navigate to GitHub, since users are low tech… make sure it download the latest versions… users should see the latest version at a first glance… make sure users won't lose any settings/configurations each update."

## What Dia does

diabrowser.com (studied 25 October 2026): one pill button, "Download Dia for free ↓", in the page and pinned to the bottom of the screen. It downloads directly, with no page in between. Under it sits one quiet line, "Available for macOS and Windows". The release notes open with the version and date ("v1.54.0 · October 22, 2026"). There is no file-format talk and no third-party page on the way.

## Decision

- **Version first.** The download band opens with "Bản mới nhất **2.1.1** · phát hành ngày 24/10/2026", and the bottom bar carries the version beside "Tải OfflineMask". The app never checks for updates (0137), and Settings already tells users to compare its version with offlinemask.com. A note under the band says where to find their version and that installing over the old one keeps everything.
- **One button, chosen for the machine.** As before, `product.js` points the button at the visitor's download: the Apple Silicon or Intel `.dmg`, or "Tải từ Microsoft Store" on Windows. Elsewhere (Linux, phones, no JavaScript) the button leads to the list of choices instead of GitHub's release page, and the list starts open.
- **Plain labels.** "Chip Apple (M1 trở về sau)", "Chip Intel (máy đời cũ)", "Microsoft Store", "Ubuntu, Debian (.deb)", "Fedora (.rpm)". The SHA256SUMS and release-notes links left the band. Both are GitHub pages, and the technical install guide (`docs/install.md`) still covers checksums. Footer links to the source code and release notes stay, for people looking for them.
- **Windows is the Store.** `storeId` is set, and the build-time `windows-direct`/`windows-store` variants from 0117 are gone. The link is the official listing page (`apps.microsoft.com/detail/…`), where Windows offers to open the Store app. The `ms-windows-store:` scheme was not used, because on a PC whose IT has disabled the Store it does nothing. An undocumented `mode=direct` parameter was not used either. "Máy không có Store?" leads to the install guide, which links the `.exe` directly.
- **Always the newest published files.** Previously the links were built from `desktop/package.json`, so a version bump pushed before its release was published (the tag builds for 10–20 minutes, then the draft is published by hand) deployed links that returned 404. The page also linked a Linux `.AppImage` that no release has had since 0104. The Vite build now reads `releases/latest/download/SHA256SUMS.txt`. That URL is not the rate-limited API, and GitHub resolves it to the newest published, non-draft release. The build takes the version from its file names, the date from `CHANGELOG.md`, and turns each `__OM_DOWNLOAD__/<file>` into a direct link, failing if the release lacks the file. In CI an unreadable release fails the build, so Cloudflare keeps serving the previous deploy. Publishing a release does not trigger a deploy; the release guide now says to push afterwards.

## Settings across updates

What a user keeps lives outside the app bundle. The vault, history and recognition pack are in `app_local_data_dir()`, and the theme and other preferences are in the web view's `localStorage`. Both are keyed to the identifier `dev.offlinemask.desktop` (Application Support on macOS, `%LOCALAPPDATA%` on Windows, `~/.local/share` on Linux). Replacing the `.app`, installing a newer `.exe`/`.msi`, or upgrading the `.deb`/`.rpm` leaves them in place. The localStorage origin also matters: Windows serves the app from `http://tauri.localhost`, and turning on `useHttpsScheme` would change the origin and empty that storage. Store updates keep the package's `LocalCache` while the package Name and Publisher stay the same. `desktop/tests/update-keeps-data.test.mjs` pins the identifier, the absence of `useHttpsScheme`, and the Store identity.

One case does not keep data. Moving from the downloaded installer to the Store starts fresh, because the package's writes are redirected to its own `LocalCache` (0117). The install guide says so and tells people who installed from the file to keep updating with the file.

## Verification

`pnpm -C landing build` resolved 2.1.1 from the live release, and every link matched a file in it. Swapping one link for `.AppImage` failed the build with "Release 2.1.1 has no OfflineMask_2.1.1_amd64.AppImage". In the in-app browser the Mac visitor got the Apple Silicon `.dmg` on both buttons. A simulated `Win32` platform got the Store listing labelled "Tải từ Microsoft Store". At 375 px with an Android user agent, the list started open and the button pointed at it, with no horizontal overflow. `pnpm test` passes. Not checked: a real Windows PC opening the Store from the listing, Intel-Mac detection, and data surviving a real Store update. That last one follows from MSIX behaviour and the pinned identity, not a test run.
