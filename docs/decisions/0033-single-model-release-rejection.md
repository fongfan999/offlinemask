# 0033 — Reject both evaluated single-model checkpoints for release

Date: 19 September 2026. Status: final technical decision for these frozen checkpoints and the current scope; owner example review pending.

The owner authorized a final bounded comparison of Underthesea INT8 and the existing BigMed INT8 control, resource measurement for the stronger engineering candidate, and a small human review set. Both candidates were assessed on the same corrected shared policy, canonical NFC inference handling, original source mapping and unchanged six-category scope.

**Neither checkpoint qualifies as the release default.** Underthesea covers 463/470 annotated values under their own selected categories, but masks 270 ordinary lexical positions and fails regression excess-masking/negative-case screening. BigMed covers 448/470 and masks 90 ordinary positions; its name coverage is only 88/103 regression and 35/39 challenge. Restricting BigMed predictions to contextual categories reduces unwanted masking to 21 positions without losing observed coverage, but its name and negative-case failures remain. Do not select a candidate merely because aggregate coverage exceeds 95%.

The frozen ranking identifies Underthesea as the stronger engineering candidate by own-category coverage, with 205,505,260 bytes of required assets versus BigMed's 872,644,599 bytes. These are uncompressed graph/config/tokenizer payload totals, not installer sizes. The two isolated offline resource probes pass the developer targets on the M1 Pro: worst warm p95 129 ms for 2,000 characters, 3.008 s for 50,000 characters and 724,889,528 bytes sampled process-tree footprint. Resource feasibility does not reverse quality rejection or qualify a packaged runtime.

The [report](../evaluations/single-model-decision-v1.md) preserves the comparison, the contextual-only ablation, failures, raw hashes and resource limits. BigMed has 377 new case executions; Underthesea's 362 canonical results are reused from the previous actual inference run and exactly replayed through unchanged policy. All 151 application tests pass. No weights, production detector, UI, dependencies or pack are changed by this decision.

The [12-case owner review](../evaluations/single-model-decision-v1/review.md) remains pending. It is a review of previously observed synthetic examples, not a fresh independent accuracy set, and no model selection or annotation approval is inferred from preparing it. Record future answers against the text/output hashes without overwriting frozen evaluation annotations. Only a reviewed new version can change evaluation expectations.

Close release selection for these unchanged checkpoints under the current criteria. Keep the existing pair as a development control only; it was not qualified by earlier evaluations either. Do not silently default to the pair, create another ensemble, lower thresholds, reinterpret user review as blanket approval, or resume custom training. A future release decision needs new qualifying evidence: corrected independently reviewed expectations, a materially different maintained checkpoint, or explicitly agreed narrower product scope. The current task authorizes none of those as an automatic next mutation. Manual review of the delivered cases is the immediate next input.
