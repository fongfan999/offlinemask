# 0037 — Select a coverage-first v1 integration candidate

Date: 19 September 2026. Status: model selection made; desktop integration and release qualification remain unfinished.

The owner explicitly reaffirmed automatic Vietnamese name, address and organization detection as a release requirement. An assisted/manual-only beta does not satisfy that requirement. The owner then authorized choosing the model(s) with the highest measured success for the first release, with specialist AI engineering expected later. Size is secondary to detection quality; the default installer remains small and recognition resources remain one optional, manually downloaded pack. No permission to weaken quality checks, claim field accuracy, or collect user data is inferred.

Select **Underthesea INT8 + OpenMed BigMed INT8 + OpenMed mSuperClinical INT8** as the **v1 integration candidate**. Restrict model evidence to names, addresses and organizations (`TEN`, `DIA_CHI`, `TO_CHUC`); use the unchanged shared rules for structured identifiers and credentials. Infer on canonical NFC and restore original source offsets before the shared reconciliation/filtering step. Remove SuperClinical from this target recipe: adding it recovers no additional complete values in this comparison and increases unnecessary masking.

This is a measured overlapping ensemble, not a claim that the models have disjoint specialties. Compared with removing one component from the selected trio, Underthesea adds three fully covered values, BigMed adds one, and mSuperClinical adds four. Additional masking also increases. The [selection manifest](../evaluations/quality-first-v1/selection.json) records exact per-component gains and losses, revisions, artifact hashes, order, category scope and integration blockers.

Selection follows a frozen ranking: passing existing floors first, then complete own-category sensitive-value coverage, then less ordinary masking, fewer checkpoints and smaller assets. All thirty recipes fail the existing floors. The selected recipe leads sensitive-value coverage with 496/500 values across 386 synthetic case records; only 345/386 cases match the lexical expectations completely. Underthesea alone has lower sensitive-value coverage (489/500), but more fully matching cases (360/386). The selected recipe is therefore the coverage-first choice, not the best on every measure.

The trio changes 26/92 negative cases and masks 482 ordinary lexical positions. Its 24-case owner-approved batch covers 29/30 values under their correct options, including 7/8 names, 4/4 addresses and 4/4 organizations, while adding 128 ordinary lexical positions. Four incomplete values remain across the ranked corpus: three lowercase names and one lowercase address. No threshold, annotation, rule or case-specific model routing was changed to hide these failures. The pack's pinned assets total 2,010,500,536 bytes (~2.01 GB), before installer/compression/runtime overhead. The 1.14 GB Underthesea+mSuperClinical alternative covers 495/500; BigMed's extra ~873 MB gains one lowercase address in the reviewed batch. This tradeoff is explicit under the owner's coverage-first direction.

The newly authorized larger AITeamUIT GLiNER2 candidate remains unscored, for a different reason from the prior size decision. Comparing its safetensors tensor names/shapes against stock GLiNER2 2.0.0 finds two trained scoring parameters that the runtime has no implementation for. The model card's linked implementation repository could not be retrieved. Do not remove those weights, invent their behavior, or call this an accuracy failure. Only metadata/tokenizer/config assets and the checkpoint header were retrieved; full weights were unnecessary after compatibility failed. A matching publisher implementation is needed to evaluate this candidate faithfully.

Four runnable checkpoints were freshly executed on the same 398 case executions each: 362 historical records, 24 approved records and a separately reported 12-case overlapping owner overlay. All 1,592 executions finish without errors. Thirty policies are replayed through the unchanged core, with exact verification of all six option previews and metrics. These are already-observed synthetic selection cases, not a fresh holdout, a training dataset, banking field accuracy or a universal model ranking.

This decision supersedes the “stop selection with no candidate” direction in Decision 0036. It does **not** reverse earlier quality failures or silently replace the installed pack. The app still uses its prior development manifest. Next implementation must preserve the tested native/reference tokenizer behavior in an offline production adapter, distribute the converted Underthesea artifact through a verified pack, and qualify actual desktop resource usage. The release quality gate remains **NOT_PASSED**. Automatic contextual detection remains required; review controls supplement it and do not fulfill the unmet requirement by themselves.
