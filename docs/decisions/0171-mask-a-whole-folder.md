# 0171 — Mask a whole folder: survey, mask, review once, save a mirrored folder

Date: 28 October 2026. Status: prototype. The owner asked whether a whole folder could be masked, then set the shape: review spreadsheets sensibly across many files, process in parallel within what the machine can take, warn when a folder is large, accept a dropped folder like a dropped file, and, for a folder too big for one computer, suggest a dedicated OfflineMask machine for the person's work or company instead of a "contact us".

## Why

People keep documents in folders: a year of bank statements, a client's contracts, a team's exports. One file at a time asks them to repeat the same three steps dozens of times and gives every file its own aliases, so the AI cannot tell that `[TEN_1_ab12]` in one contract and `[TEN_3_9f0c]` in the next are the same person.

## What the prototype does

- **Entry.** A folder (or several files) dropped on the home start box, or picked with "Chọn cả thư mục" beside it, opens the folder page. Only home offers the picker, because a folder may mix documents and spreadsheets and a link on the Word or spreadsheet page reads as "a folder of these only"; a folder dropped on those pages still opens the folder page rather than failing. A folder being masked or reviewed is listed in the sidebar with its status, so the folder page can be found again while a long run continues in the background (decision 0172 replaced the format entries this first sat beside). Word, OpenDocument, PDF, text and spreadsheet files are taken; everything else is listed as skipped with the reason; system litter (`.DS_Store`, `~$` lock files, hidden files) is not listed at all.
- **Survey.** Every file is opened once, counted and closed again: how much text it holds and, for each sheet, its header layout and how much text each column holds. Files that cannot be read (a password, a scanned PDF) are listed with the page's usual message. Nothing is kept open, so memory does not grow with the folder.
- **Spreadsheets by layout.** Sheets whose headers are the same (normalized like column suggestions) share one layout: twelve monthly statements are one card. Each card shows the first rows of one of its files with the same per-column hide / scan / keep choice as the spreadsheet page, suggested the same way; a choice applies to every sheet of that layout. Documents need no choice before masking.
- **Estimate and warnings.** The time is estimated from the text the model will read (documents' paragraphs, spreadsheet columns set to scan) at 2 000 characters a second plus 5 seconds to load the model (measured, see below); after a run finishes, the pace it kept is used for the rest of the launch, in RAM; it updates as layout choices change, and the progress line during the run uses the measured pace. Above an hour, the page says so and adds: "Nếu thường xuyên cần ẩn nhiều tài liệu, bạn có thể dành riêng một máy chạy OfflineMask cho công việc hoặc cho cả công ty, để máy làm việc của bạn không bị ảnh hưởng." No contact link and no price wording (owner, 28 Oct).
- **Parallel within the machine.** A new command reports the processor count and installed memory (`machine.rs`: `available_parallelism`, and `hw.memsize`, `GlobalMemoryStatusEx` or `/proc/meminfo`; no new dependency, nothing stored). Files are opened and written by a pool of file workers: one per four processors, at most one per 4 GB of memory, between one and four. The model itself runs one batch at a time, as it does today (one locked session, or one helper process in release builds), using its four threads; the pool keeps it fed, so it never waits for a file to be read or written. Running several model batches at once is left for a measured change of its own: it multiplies memory and touches the masking engine.
- **One alias table for the folder.** Every file is masked with the same alias book, so one value has one alias in every file. A text the model already read in another file (a repeated heading, a name in a cell) is not read again.
- **Review once.** After masking, the hidden values of the whole folder are listed once, with how many files each appears in. Unticking a value keeps it in every file.
- **Save.** The user picks where to put the result; the app creates `<folder> (OfflineMasked)` there (numbered if it exists) and writes each masked file at the same relative path, named as the single-file pages name them. Each file is opened again, given its edits and the kept values, written and closed. Originals are never touched. In the browser preview each file downloads.
- **Permissions.** Reading a folder uses the web view's own folder input and drop, which hand the page the chosen files and nothing else. Saving needs two new permissions: the folder dialog (`dialog:allow-open`), which adds only the chosen folder to the app's file scope, and creating folders (`fs:allow-mkdir`) inside it. The privacy page says so.

## Known limits

- No history yet. A folder's alias table lives in memory until another folder is opened or the app quits. A reply or a returned file about the folder is restored at the folder's step 3, or on "Nhận lại bản đầy đủ" (decision 0172), one file at a time; history for a folder should be one entry, not one per file (decision 0071), and restoring a whole returned folder is its own change.
- The speed was first an assumed 5 000 characters a second from decision 0025's profile of an older graph. On 29 Oct 2026 the owner's 5-file folder showed "Dưới 1 phút" and then ran for over 6 minutes. Two causes: the shipped model on the native runtime reads 1 800–2 200 characters a second on an Apple-silicon Mac (Node, onnxruntime-node, two bank statements of 1 054 rows and two PDFs: about 35 seconds in all), and plain `tauri dev` runs the model on the single-thread WASM backend, roughly ten times slower; `pnpm -C desktop desktop:dev:native` runs it at release speed. The default is now 2 000 a second plus the load, and a finished run's own pace (over 20 000 characters) replaces it, which also covers slower machines.
- Text files in a folder go through the document flow, which skips name spans without a capital letter (decision 0079); the text page keeps them.
- PDFs are read three times (survey, mask, save). Opening is cheap next to the model, but a long PDF is not free.
- Concurrency is sized once, when the folder opens; it does not back off if memory runs short during the run.

## Ready screen, reworded (29 October 2026)

The owner asked to improve the screen before masking. Its parts touched the card's edges and spoke in the code's words ("Kiểu bảng 1 · Ẩn 0 cột · quét 2 cột · giữ 252 cột", in monospace), and nothing showed which rows open. Now: one line of time ("Ẩn 4 tệp mất dưới 1 phút trên máy này."), a heading "Cột trong bảng tính" over one sentence saying the choices are made already and a group opens to change them, each group named after its example file (and sheet, unless the sheet only repeats the file's name), with its sheets and columns in words that leave out zero counts ("1 trang tính · ẩn hẳn 4 cột · tìm thông tin trong 1 cột"). Every row that opens has an icon, a name over a quiet line and a chevron that turns; "Danh sách tệp" is "Các tệp trong thư mục" with the folder's counts, and skipped files say to open the row for the reasons. Everything sits 24 px inside the card.

The time, shown. The estimate always followed the column choices (only document text and columns set to "Quét nội dung" are read; hidden and kept columns cost next to nothing). A panel that explained this, with a bar, legend and per-group times, was tried and dropped: the owner found it more than people want, since they only care how long. The time is one line at the bottom, beside the button that starts the job: a clock, "Dưới 1 phút trên máy này · thư mục gốc giữ nguyên". It still moves as columns change.

Reading the folder. While each file is read once to size the work, the card shows what the masking run shows: "Đang xem trong thư mục…" with the count on the right, a bar, the file being read (so a slow one does not look stuck), and Hủy, in place of one small monospace line.

What to do, said first. The owner found people did not know what to do on the ready screen, nor why five files showed as two spreadsheet rows. It now opens by asking for a look first: "Xem lại trước khi ẩn. Mở từng bảng tính để xem cột nào sẽ được ẩn, rồi bấm “Ẩn N tệp”." (or "Kiểm tra các tệp bên dưới, rồi bấm …" with no spreadsheet), beside an eye; a plain "Đã sẵn sàng" left people unsure there was anything to check, then "Bảng tính · N tệp" with each group named by its files ("sao-ke-thang-9.csv, sao-ke-thang-10.csv", or "A, B và 3 tệp khác") and its columns named ("Ẩn cả cột Họ và tên, Email · tìm và ẩn trong cột Ghi chú · giữ nguyên 2 cột"), a "Xem cột" label on each row, a line on grouping only when files share columns, and "Tài liệu · N tệp" naming the documents. The "Các tệp trong thư mục" list now appears only once the run starts, where it carries each file's status.

The review says what to do the same way: "Đã ẩn N chỗ trong M tệp. Xem lại danh sách bên dưới, bỏ chọn những gì không cần ẩn, rồi bấm “Lưu thư mục đã ẩn”." beside the eye, in place of a line that also counted "mã thay thế", a word people do not need. The list is titled "Những gì đã ẩn" for a folder (a folder is saved, not downloaded), and once saved one line gives both: what was hidden and where it went.

Three steps, like one file. The owner could not picture how a folder goes on after it is hidden, while a file or a text shows three steps. The folder page now carries the same stepper and names: "Ẩn thông tin" (pick, read, column choices, "Ẩn N tệp"), "Tải về và gửi AI" (review "Những gì đã ẩn", "Lưu thư mục đã ẩn", then "Đã lưu vào thư mục “…”. Gửi các tệp cần thiết trong thư mục đó cho AI. Khi AI trả lời, sang bước 3…" with "Sang bước 3: Khôi phục" and "Lưu thêm một bản") and "Khôi phục" (home's restore box, `RestoreBox`, given the folder's own codes: a pasted reply, or a returned file one at a time). Step 3 opens once the copies are saved, since that is what goes to the AI; step 1 can be reopened only before saving (`edit()` drops the masked results and their codes, and hiding again makes new ones). There is no "open in Finder" after saving: that needs a system permission and a privacy-page change of its own.
