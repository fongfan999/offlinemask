# 0130 — Quick actions read and replace natively, and only borrow the clipboard

Date: 23 October 2026. Status: requested by the owner ("fix all six, can the app work without using users clipboard?") after an audit of how the circle and ⌘⇧M used the clipboard.

## What surprised users

1. Anything that was not plain text on the clipboard (an image, files, rich text) was replaced: the clipboard was read as text and "put back" as text, on every click.
2. A copy made while masking ran could be overwritten by the old clipboard, or by the result.
3. The raw selection, an invisible marker and restored real values passed through the clipboard, where clipboard managers recorded them and Universal Clipboard sent them to other devices.
4. A replaced result stayed on the clipboard, over whatever the user had copied.
5. A page killed mid-action (0128) could leave the marker or the raw selection on the clipboard.
6. An application that copies something else when nothing is selected (a whole line, in some editors) had that taken as the selection.

## Can it work without the clipboard?

Measured on this Mac with Accessibility, in TextEdit and in a separate Chrome on a test page:

| Field | Read the selection | Replace it |
| --- | --- | --- |
| Native text view (TextEdit) | exact | works (`AXSelectedText` write, value changes) |
| Chrome textarea, input | exact | **ignored**: the write reports success, the page does not change |
| Chrome rich editor (contenteditable, like ChatGPT's box) | **loses line breaks** | ignored |
| Read-only web text | works | — |

Typing the result as key events would avoid the clipboard, but Vietnamese input methods (Telex) rewrite typed letters and a typed line break sends a chat message. So in browsers and Electron apps, where most masking happens, the copy and paste chords stay; native macOS apps need neither.

## Decision

- **Native first (macOS).** When the focused element is a native text view (it answers `AXSelectedText` but no web text markers), the selection is read and replaced through Accessibility. A replacement counts only when the field's value changed and holds the result; otherwise the paste path runs.
- **Borrow, in native code.** Elsewhere `quick_copy_selection` and `quick_replace_selection` (`src-tauri/src/quick_input.rs`, `clipboard_guard.rs`) save the whole clipboard (every item and type on macOS; every memory format on Windows; text on Linux), write an empty private item, send the chord, wait for the clipboard to change (at most 600 ms), read it, and put the saved clipboard back. A paste holds the result for 500 ms, then restores. Each restore happens only if the clipboard is still as OfflineMask left it, so a copy the user made in between is kept. The whole round trip runs in Rust, so a killed page cannot interrupt it.
- **Private writes.** OfflineMask's own items carry `org.nspasteboard.TransientType`, `ConcealedType` and `AutoGeneratedType` and are written with `NSPasteboardContentsCurrentHostOnly` (no Universal Clipboard); on Windows `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0 and `CanUploadToCloudClipboard` = 0.
- **The result does not stay.** After an in-place replace the clipboard holds what it held before. When the result cannot be put in place (no exact read, the selection moved, the paste failed), it opens in the preview card in the corner, and its copy button is the only way it reaches the clipboard.
- **A copy must match.** The copied text must be part of what Accessibility reported, whitespace aside; otherwise it is not used.
- **What still uses the clipboard by design:** the panel's own buttons and the macOS Service, which act on the clipboard on purpose, and the preview's copy button.

## Verified

On macOS with an image on the clipboard: TextEdit replaced in 0.2 s through Accessibility; a Chrome textarea and a rich editor were replaced by the guarded paste, line breaks kept; the image was on the clipboard afterwards each time. The Windows implementation is type-checked against `windows` 0.62.2 but not run; it needs a check on a Windows machine.

## Limits

The copy chord's own write comes from the other application, unmarked; a clipboard manager polling faster than the round trip (well under a second) can still record the raw selection. A plain-text paste into a bare rich editor can turn a blank line between paragraphs into several; the old flow pasted the same text.
